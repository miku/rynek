# Proposal: Minimal Dependency Resolver and Runner (mdrr)

status: draft
date: 2026-07-24

## Context

`articleindexd` (see `span/notes/2026-07-22-articleindexd.md`) wants to replace
luigi with a small, file-driven task runner baked into a single Go binary. This
document proposes the skeleton for that runner as a **standalone, generic
library** -- `rynek` / mdrr -- so it can be developed and tested in isolation
before articleindexd depends on it.

The essence we are reimplementing from luigi is small:

1. A **task** has a stable identity and declared **dependencies** (a DAG).
2. A task produces a **target**; *target exists == task complete* (idempotency).
3. A **runner** resolves the DAG, runs only what is missing, respecting
   dependency order and a concurrency limit.

Everything expensive in articleindexd is an external process (`span ...`,
`zstd`, `sort`, `solrbulk`) streaming over zstd line-delimited JSON. The runner
itself does no heavy lifting: it schedules, checks file existence, shells out,
and logs. It must stay tiny, dependency-light, and debuggable.

## Goals

* A ~few-hundred-line core: `Task`, `Target`, `Runner`, plus file/command
  helpers. Standard library first; at most `golang.org/x/sync`.
* Existence-based completeness (luigi semantics), with optional mtime staleness.
* Correct handling of **diamond dependencies** (a shared upstream runs once).
* Bounded parallelism across independent branches.
* Deterministic, inspectable artifacts on disk -- any intermediate can be
  examined; a rebuild is just "delete the artifact and re-run."
* A thin CLI: `run`, `deps`, `status`, `gc`, `--dry-run`, `--force`.

## Non-goals

* No central scheduler daemon, no message broker, no database. The filesystem
  is the state store; one `run` invocation walks and executes.
* No distributed execution. Single host, many cores.
* No dynamic task graphs mutating mid-run (luigi's dynamic deps). Requires() is
  evaluated up front per task instance.
* Not a general workflow engine -- just enough to build the index.

## Design decisions

**D1 -- Completeness = target exists (default).** A task is skipped iff its
output target reports `Exists() == true`. Rebuilds are explicit (`rm` the
artifact or `--force`). This matches siskin/luigi and keeps the model trivial to
reason about. Mtime-based staleness (make semantics) is available opt-in per
target (`StaleIfOlderThan`) but off by default -- dated artifacts rarely need
it and it invites surprising cascade rebuilds.

**D2 -- Identity is a stable string `Key()`.** e.g.
`"CrossrefSnapshot(date=2026-07-24,feed=2)"`. Keys dedup shared dependencies in
the graph and memoize execution within a run. Two task values with the same key
are the same node.

**D3 -- Tasks are Go structs implementing an interface.** Parameters (date,
source, style) are struct fields; `Requires()` returns concrete upstream task
values. This keeps dependencies type-checked and refactorable (unlike a
stringly-typed config DAG), while a **registry** (D7) still allows
instantiation by name from the CLI.

**D4 -- Concurrency via per-key `sync.Once` + a semaphore.** Each task key gets
one memoized execution guarded by `sync.Once`; a shared upstream therefore runs
exactly once even when pulled by several parents. Dependencies run concurrently
via `errgroup`; a counting semaphore bounds the number of *Run* calls in flight
(`--workers`). This composes diamonds correctly without an explicit topological
sort. (Kahn's algorithm is a viable alternative but needs its own dedup/ready
bookkeeping; the once+semaphore model is shorter and just as correct.)

**D5 -- Atomic outputs.** `Run` writes to a temp file and renames into place, so
a crash never leaves a half-written artifact that later reads as "complete."
The `FileTarget`/`Cmd` helpers enforce this.

**D6 -- Fail-fast, with context cancellation.** The first task error cancels the
run context; in-flight external processes receive `SIGKILL` via
`exec.CommandContext`. A `--keep-going` flag can relax this later. Every task's
start/skip/finish/error is logged with its key and duration (`log/slog`).

**D7 -- A registry maps names to constructors** so the CLI can build a root task
from `run <Name> --date ...`. Params passed as a small typed struct.

## Core API

```go
package rynek

// Target is a build product whose presence signals completion.
type Target interface {
	// Exists reports whether the product is present (and, if the target
	// implements staleness, still fresh).
	Exists(ctx context.Context) (bool, error)
}

// Task is a unit of work with a stable identity and declared dependencies.
type Task interface {
	// Key uniquely identifies this task instance, params included.
	Key() string
	// Requires lists upstream tasks that must complete first. May be nil.
	Requires() []Task
	// Output is the target that marks this task complete. May be nil for
	// pure "wrapper" tasks that only group dependencies.
	Output() Target
	// Run produces Output. Called only when Output is absent (or --force).
	Run(ctx context.Context) error
}
```

## Runner and execution

```go
type Runner struct {
	Workers int          // max concurrent Run calls; default = runtime.NumCPU()
	Force   bool         // ignore existing outputs, always Run
	DryRun  bool         // resolve + print, never Run
	Log     *slog.Logger

	sem  chan struct{}
	mu   sync.Mutex
	memo map[string]*node // key -> memoized execution
}

type node struct {
	once sync.Once
	err  error
}

// Run resolves and executes the DAG rooted at root.
func (r *Runner) Run(ctx context.Context, root Task) error {
	r.sem = make(chan struct{}, max(1, r.Workers))
	r.memo = make(map[string]*node)
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()
	return r.exec(ctx, root)
}

// exec memoizes so each task key runs at most once per invocation.
func (r *Runner) exec(ctx context.Context, t Task) error {
	r.mu.Lock()
	n, ok := r.memo[t.Key()]
	if !ok {
		n = &node{}
		r.memo[t.Key()] = n
	}
	r.mu.Unlock()

	n.once.Do(func() { n.err = r.execOnce(ctx, t) })
	return n.err
}

func (r *Runner) execOnce(ctx context.Context, t Task) error {
	// 1. Resolve dependencies concurrently.
	if deps := t.Requires(); len(deps) > 0 {
		g, gctx := errgroup.WithContext(ctx)
		for _, d := range deps {
			d := d
			g.Go(func() error { return r.exec(gctx, d) })
		}
		if err := g.Wait(); err != nil {
			return err
		}
	}

	// 2. Completeness check (unless forced).
	if !r.Force && t.Output() != nil {
		ok, err := t.Output().Exists(ctx)
		if err != nil {
			return err
		}
		if ok {
			r.Log.Debug("skip (complete)", "task", t.Key())
			return nil
		}
	}

	if r.DryRun {
		r.Log.Info("would run", "task", t.Key())
		return nil
	}

	// 3. Acquire a worker slot and run.
	select {
	case r.sem <- struct{}{}:
	case <-ctx.Done():
		return ctx.Err()
	}
	defer func() { <-r.sem }()

	start := time.Now()
	r.Log.Info("run", "task", t.Key())
	if err := t.Run(ctx); err != nil {
		r.Log.Error("failed", "task", t.Key(), "err", err)
		return fmt.Errorf("%s: %w", t.Key(), err)
	}
	r.Log.Info("done", "task", t.Key(), "took", time.Since(start))
	return nil
}
```

Notes:

* The `sync.Once` per key is the crux: even if two parents call `exec` on the
  same upstream concurrently, the map lookup is mutex-guarded and `once.Do`
  serializes the single execution; both parents observe the same `err`.
* Dependency resolution is *not* gated by the semaphore -- only `Run` is -- so a
  deep graph does not deadlock waiting for slots while merely checking
  existence.

## Built-in helpers

```go
// FileTarget is a local file; existence == the file is present.
type FileTarget struct {
	Path string
	// StaleIfOlderThan, if set, also requires the file be newer than these
	// inputs (make semantics). Empty => existence only (default).
	StaleIfOlderThan []string
}

func (f FileTarget) Exists(ctx context.Context) (bool, error) { /* stat + optional mtime compare */ }

// Atomic writes a file via temp + rename, so partial output never looks complete.
func Atomic(path string, fn func(w io.Writer) error) error { /* tmp, fsync, os.Rename */ }

// Cmd runs a shell pipeline with context cancellation; used by tasks that
// wrap external tools (span, zstd, sort, solrbulk). Renders {placeholders}.
func Cmd(ctx context.Context, tmpl string, args map[string]string) error {
	// exec.CommandContext("bash", "-o", "pipefail", "-c", rendered)
}
```

`Cmd` deliberately shells out to `bash -c` with `pipefail` because the real work
is unix pipelines (`zstdcat ... | span tag ... | zstd -c > out`). Keeping that
as a string mirrors siskin's `shellout` and stays readable. Tasks that write
files should route the final artifact through `Atomic` (write temp path, then
`os.Rename` to `Output().Path`).

## Registry and CLI

```go
type Params struct {
	Date    time.Time
	Extra   map[string]string // source, style, feed, ...
}

// Register wires a task name to a constructor for CLI instantiation.
func Register(name string, ctor func(Params) Task)
```

```
rynek run <Task> [--date YYYY-MM-DD] [--workers N] [--force] [--dry-run] [-v]
rynek deps <Task> [--date ...]        # print the resolved DAG (indented / dot)
rynek status <Task> [--date ...]      # which targets exist / are missing
rynek gc [--home DIR] [--older-than 30d] [--keep-latest]   # disk cleanup
```

`run` looks up the constructor, builds the root `Task`, and calls
`Runner.Run`. `deps`/`status` reuse the same graph walk with `DryRun`-like
traversal (no `Run`, just print / stat). `gc` walks the artifact home and
deletes by age, preserving `latest` symlinks -- covering articleindexd's
"periodic cleanups to preserve disk space" requirement.

## Implementation milestones

1. **Core + tests.** `Task`/`Target`/`Runner`, `FileTarget`, `Cmd`, `Atomic`.
   Table tests for: linear chain, diamond (upstream runs once), skip-on-exists,
   force, dry-run, failure cancels siblings. Use in-memory fake targets/tasks.
2. **CLI.** `run` + `deps` + `--dry-run`/`--force`/`--workers`. slog output.
3. **Porting spike.** Model the `ai.py` happy path (6 sources -> AIExport +
   AIRedact) as rynek tasks; run against a small fixture; compare output
   bytes to a siskin run.
4. **status + gc.** Existence report; age-based cleanup preserving `latest`.
5. **Freshness for acquisition.** `span crossref sync` "run until caught up"
   task whose Output is the dated snapshot; validate it composes with the
   exists-based model.

## Testing strategy

* Pure-Go unit tests with fake `Task`/`Target` (a counter target that flips to
  "exists" after Run) -- no external tools needed for graph logic.
* A `race`-enabled test hammering a diamond graph to prove single execution.
* An `example/` integration test using `echo`/`cat`/temp files as stand-in
  "external tools" to exercise `Cmd` + `Atomic` end to end.

## Open questions

* **Params typing.** Keep `Params{Date, Extra map[string]string}` generic, or
  generate per-task typed constructors? Start generic; revisit if the registry
  gets unwieldy.
* **Staleness scope.** Is existence-only ever wrong for us (e.g. config changes
  upstream of a cached artifact)? Likely handled by dating the config freeze
  into the key; confirm during the porting spike.
* **Long-running acquisition** loops (`crossref sync`): task that runs to
  "caught up as of date," then the snapshot task keys the artifact. Verify no
  awkwardness with cancellation.
* **Where does the runner live** long-term -- separate `rynek` module imported
  by articleindexd, or folded directly into the span binary? Prototype here,
  decide at milestone 3.
* **Structured run report.** Emit a machine-readable per-task summary
  (key, status, duration, bytes) for the grafana/monitoring requirement?
